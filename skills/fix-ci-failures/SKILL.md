# fix-ci-failures

Находит причину падения сборки и исправляет код. Скрипты — Python 3 (только stdlib), лежат в `scripts/`.

## 0. `.env`

Ключи имеют уникальный префикс `CIFIX_`, чтобы не конфликтовать с другими настройками проекта:

```
CIFIX_GITLAB_URL=    CIFIX_GITLAB_TOKEN=   (токен: scope read_api)
CIFIX_SONAR_URL=     CIFIX_SONAR_TOKEN=
```

Любой скрипт: если `<корень репо>/.env` нет — создаёт его; если он уже есть — **дописывает в конец только недостающие** `CIFIX_*` ключи (остальное содержимое не трогает). Также добавляет `.env` в `.gitignore`. Если обязательные значения пусты — завершается с кодом 2: попросите пользователя заполнить `.env` (не просите токены в чат, не печатайте и не коммитьте их) и повторите. Переменные окружения с теми же именами имеют приоритет над файлом.

## Сценарий 1: по локальной ветке

1. `python <skill>/scripts/gitlab_mr.py` (опции: `--branch`, `--mr IID`, `--tail N`). Скрипт берёт проект из `origin`, ищет MR ветки, берёт последний pipeline и для каждой упавшей job выводит ключевые строки и хвост лога. Найденные Sonar-ссылки печатаются в `SONAR_LINKS`.
2. Классифицируйте упавшие jobs:
   - **Unit-тесты**: найдите упавший тест в логе, воспроизведите локально той же командой, что в job (см. `.gitlab-ci.yml`), исправьте код (или тест, если он устарел — объясните почему), перезапустите.
   - **Sonar** (`ERROR: QUALITY GATE STATUS: FAILED - View details on <url>`): перейдите к сценарию 2 с этой ссылкой.
   - **Прочее** (компиляция, lint, зависимости): исправьте по тексту ошибки.

## Сценарий 2: прямая ссылка на Sonar

`python <skill>/scripts/sonar_issues.py "<url>"` — url вида `https://sonar/dashboard?id=KEY&pullRequest=154` (или `&branch=`). Выводит статус Quality Gate с нарушенными условиями, нерешённые issues (severity, файл:строка, правило, сообщение), security hotspots и метрики нового кода.

Исправление:
- Issues/hotspots: откройте файл по `файл:строка`, исправьте причину по сути правила, а не подавлением (`@SuppressWarnings`, `// NOSONAR` — только с обоснованием и согласием пользователя).
- Падение по покрытию/дубликатам на новом коде: добавьте тесты на непокрытые строки / уберите дублирование.
- Правило непонятно: `/api/rules/show?key=<rule>` через `sonar_get` из `scripts/common.py`.

## Завершение

- Запустите локально тесты/линтер затронутого модуля.
- Кратко отчитайтесь: что упало, причина, что изменено, что не удалось проверить локально (Sonar-скан пересчитается только после push).
- Не делайте commit/push без просьбы пользователя.

## Ограничения

- Токены используются только для запросов к `CIFIX_GITLAB_URL` и `CIFIX_SONAR_URL`.
- Скрипты только читают данные (GET).
- Лог job может быть большим — скрипт обрезает вывод; при необходимости читайте полный trace: `GET /projects/:id/jobs/:job_id/trace`.
